# Source-owned review refactor (phase 1)

Use source-owned structural span IDs and exact rendered coordinates, not inferred cross-language boundaries. Immutable maps bind both artifact hashes and each paired interval. Corrections must reproduce the actual candidate; ambiguous cross-span edits invalidate map reuse. ID-addressed independent findings compile to the pinned v2 exact anchor schema and retain prior lineage and canonical validators. No source changes or silent pin upgrades. This commit supplies primitives and tests; runtime wiring and capacity proof remain separate.


Phase 2: accepted structural and correction artifacts now persist source/target hash-bound map files. New plain-prose reviews use source-owned mapped partitions and deterministic passage ID evidence. Small local corrections may use one canonical focused_candidate bounded follow-up, including all changed spans, previous open findings and adjacent spans. It requires the previous full independent report, unchanged literary memory, verified old/current maps and the canonical delta. The reviewer can request FULL_REQUIRED rather than endorse incomplete evidence. No speculative cross-version reuse. No protected EPUB marker/link inputs are routed to the ID-only reviewer yet. More work remains on grouped correction edits, mapped retry refinement, shared ChatOps authoring interfaces and throughput proof.


Phase 3: mapped correction groups pack full source-owned context once per passage, select up to twelve disjoint exact reviewer-anchored edits within 20k combined core characters, and retain existing limits on repeated/critical/structural/ambiguous work. Independent preflight compares the actual combined candidate for a complete mapped span, not synthetic unaligned excerpts. The single-review policy still applies per risky case. No overlap is marked resolved, no anchor is expanded, all existing canonical rechecks remain required. Addressed response protocol defects use the established bounded recovery classification. The feature is gated by the same span-map flag; no production change.


Phase 4: provider-size recovery can now split an unfinished mapped review core at a real paired span boundary. Complete independently reviewed windows are preserved under exact artifact and memory binding. Rebuild stable refined partitions after a local edit; if exact geometry changes, only byte-identical clean windows with identical source scope and target-core geometry may be reused. A changed glossary/style revision still forces fresh evidence. No old report is synthesized or promoted by recovery.


Phase 5: the existing ChatOps bridge now accepts an optional `structural_segments` object on `accept-translation`, using the same immutable public structural helper and exact-render check as Auto. It writes the same book-local hash-addressed map in the same canonical acceptance/receipt commit. An optional `addressed_parts` array on `review-record` replaces (not supplements) `quality_report`. The bridge reconstructs every current packet from the accepted source/target bytes and map, compiles every independently supplied response using the common ID compiler, verifies coverage/lineage/outcome, then delegates to the existing pinned `review-record` CLI. Live claim, artifact hashes and distinct reviewer sessions remain mandatory. Shared memory proposals use the existing separate canonical CAS path (addressed ChatOps responses must provide empty glossary/style arrays). Legacy request envelopes remain supported. No new queue or parallel lifecycle.

Read-only packet utility, from the locked public runtime checkout:

```sh
python automation/span_exchange.py translation-plan --source extracted.md --engine /path/to/public-engine
python automation/span_exchange.py review-plan --source extracted.md --translation accepted.md --map exact-map.json --previous previous-record.json
```

Omit `--previous` for the initial independent review. Translation output uses the returned source segment IDs; submit `structural_segments` as ID-to-translation object, along with the exact rendered `translation`. The bridge rebuilds the plan rather than trusting arbitrary map coordinates. For review, submit each `{"chunk_id":"chunk-001","response":{...}}` exactly once in `addressed_parts`, with checks/findings/output schema of the shared ID reviewer. The canonical CLI still owns quality and acceptance; the utility neither creates evidence nor calls a model. Existing workspace files are never silently changed. Plain prose only for addressed review until protected-marker support is verified; other units retain canonical existing evidence format.


Phase 6: ChatOps can submit `correction_patches` together with `previous_review_record_id` on the existing `accept-translation` operation, instead of structural_segments. The bridge reloads the exact preceding rejected v2 record and current canonical acceptance, validates the same reviewer-bound intents with the pinned public correction protocol, reproduces the submitted candidate bytes, checks protected structure, suspicious content loss and new repetition, and rebases the shared map only when ownership remains exact. No arbitrary map supplied by caller is accepted. Partial corrections do not resolve findings. The canonical independent review after acceptance is still mandatory; the ChatOps executor does not itself invoke an extra semantic model veto. Auto's optional extra veto remains an execution-side safeguard. Use a distinct independent Reviewer chat session; the bridge cannot attest to the model's literary judgment or hidden conversation history. All canonical acceptance remains in the original pinned CLI.
